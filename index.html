How it works

  1. Scan. The app reads the 4,377-byte header before every file (name, size, date, path) and maps the archive. File contents are referenced as slices — not loaded yet.
  2. Zip. Each entry is handed to the ZIP writer straight from the original file bytes and compressed locally.
  3. Download. A temporary link is created for the finished ZIP. No server, no queue, no retention.

Limitations

  • Plain (free-version) backups only. Backups with Pro chunk compression or password encryption are detected and refused with an explanation.
  • Very large sites need RAM roughly 3–4× the backup size during compression.
  • File dates are preserved; CRC integrity values from the archive are informational.
